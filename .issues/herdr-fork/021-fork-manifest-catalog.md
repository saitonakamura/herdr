## Question

Fork builds fetch remote detection manifests from herdr.dev
(`src/detect/manifest_update.rs`, `https://herdr.dev/agent-detection/index.toml`), and a
remote manifest wins over the bundled one when its version is higher. So any fix the
fork makes to a bundled manifest (005, 006) is shadowed the moment upstream publishes a
newer one. Found by 005 on 2026-10-15.

Point fork builds' default catalog at a catalog served from the fork's `master` (for
example raw GitHub files, generated by a script or CI from `src/detect/manifests/`), so
the fork's manifests hot-update as upstream's do and upstream's manifest changes arrive
through upstream syncs. `HERDR_AGENT_DETECTION_MANIFEST_CATALOG_URL` keeps overriding
it. Document in FORK.md that a sync must keep the catalog current, and check that a
local override in `~/.config/herdr/agent-detection/` still wins.

This changes the 2026-10-15 decision "keep `manifest_check`" only in where the
manifests come from: upstream's still arrive, through the sync.
